# Alcance del producto

## Estado

Documento técnico derivado de las decisiones explícitas del usuario y del Master Context Pack. Si cambia el alcance comercial, validar primero la fuente oficial en Google Drive.

## Producto base

Una landing mobile-first de una sola página para un comercio local, construida con bloques reutilizables y orientada a una acción principal.

El producto base contempla:

- entre cinco y siete bloques visuales;
- servicios;
- ubicación y horarios;
- redes y canales de contacto;
- CTA principal;
- formulario o canal de contacto;
- diseño responsive;
- SEO técnico básico;
- favicon;
- una ronda consolidada de revisión;
- conexión de dominio únicamente después de aprobación y venta.

## Fase actual

La fase de validación técnica debe demostrar:

1. Un template reutilizable.
2. Un negocio ficticio de nails.
3. Datos estructurados separados de la presentación.
4. Un preview funcional con `noindex` y etiqueta de concepto no oficial.
5. QA reproducible.
6. Documentación suficiente para repetir el flujo.

## Fuera de alcance de la fase

- Automatización completa del negocio.
- Panel administrativo.
- Plataforma multi-tenant de producción.
- Ecommerce.
- Cuentas de usuario.
- Calendario o booking propio.
- Procesamiento de pagos dentro de la landing.
- Compra o transferencia real de dominios.
- Uso de datos personales o assets reales no autorizados.
- Software a medida para clientes.

## Booking

Decisión vigente: en la primera etapa se integra una herramienta externa existente y propiedad o responsabilidad del cliente. La selección de proveedor y el flujo detallado siguen pendientes.

## Gates del preview

Un preview se considera válido cuando:

- es claramente ficticio o está marcado como concepto no oficial;
- no está indexado;
- no utiliza assets reales sin autorización;
- carga y funciona en móvil y escritorio;
- tiene CTA y navegación utilizables;
- pasa las verificaciones técnicas definidas para la fase;
- puede generarse o adaptarse dentro del presupuesto de tiempo que se medirá en el piloto.

## Cambio de alcance

Todo cambio que introduzca nuevas páginas, datos sensibles, pagos, booking propio, autenticación, proveedores o costos recurrentes requiere revisar los ADR y, cuando corresponda, crear una decisión nueva.
